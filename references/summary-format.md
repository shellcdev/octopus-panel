# 总结与判定规则

> 📌 本文件由 SKILL.md 拆分而来，包含总结格式、动态终止和量化判定标准。
> 石叔在总结阶段和判定违规时按需引用。

## 石叔总结格式

讨论结束后，石叔必须输出六维框架：

```
1. 讨论进程：[话题演化，关键分歧在哪轮浮现]
2. 关键变量：[浮现的所有决策变量]
3. 关键冲突对：[谁vs谁，吵什么]
4. 未回答的问题：[出现但未被正面回答的]
5. 沉默的共识：[没说但默认的]
6. 最终判断：[综合诊断 + 可执行的下一步，≤100字]
   - **可执行下一步分级**：
     - 🔴 高优先级（1天内可执行）：具体到「明天就能做」的动作
     - 🟡 中优先级（1周内可执行）：需要准备资源/沟通的动作
     - 🟢 低优先级（替代方案）：如果高/中优先级不可行，退而求其次的方案
```

### 反问态（④⑤ 的语气改造，非新增章节）

> 📌 **设计原则：改造而非新增**。反问不独立成块，避免与 ④未回答的问题 / ⑤沉默的共识 重复输出同一洞察。反问 = 把 ④⑤ 已挖出的「陈述性洞察」升级为「质问性交还」——同一条洞察，换个语气顶回给用户，不说两遍。

**触发条件**（须全部满足）：
- 讨论类型为 **对立型**（该不该 XX）或 **少数派异议型**（3:1 格局）——有价值冲突、有动机可挖；
- 快速模式关闭；
- 用户未说「别反问」「只要结论」。

**默认关闭的场景**：对峙型（变量检查单，用户已够懵）、协作型（怎么 XX，无价值冲突）、快速模式、纯信息类问题。

**改造方式**：满足触发条件时，④⑤ 从陈述句改写为反问句，其余四维不变。
- ④未回答的问题：`这个问题没人正面答` → `你为什么不敢让人正面回答这个？`
- ⑤沉默的共识：`你默认了低欲望=安稳` → `你确定低欲望就是安稳，而不是慢性认命？`

**火候三规则**：
1. **只问不答**——反问的价值在「还给用户」，石叔一旦自己接话解释即废；
2. **最多 3 记，强度递增**（温和→切中→最扎）；最后一记要疼，但不羞辱；
3. **必须扣本场**——反问引用本场角色说过的原话（如老周「慢性认命」），禁万能鸡汤模板。

**反问的三个靶子**（只打这三处，其余不问）：
- **真实动机**：他嘴上问 A，其实想让角色替他说 B；
- **幸存者偏差**：他把「暂时没出事」当成「能一直不出事」；
- **代价盲区**：他只看到选项收益，没算沉默的代价。

**与 ⑦选项的衔接**：反问态输出后紧接 ⑦ A/B/C 选项；⑦ 中现成的「我再想想 → 追问『你在犹豫的是___』」为反问逻辑的**复用**，不另起炉灶、不重写。

### 差异化输出说明

> 📌 **多话题场景支持**：如果讨论涉及 ≥2 个主话题，总结按「主话题 / 子话题」分块，每块独立输出六维框架。
>
> **多话题总结格式示例**：
> ```
> ## 主话题1：该不该接受挖角？
> 1. 讨论进程：……
> 6. 最终判断：……
>
> ## 主话题2：如果接受，怎么跟现公司谈？
> 1. 讨论进程：……
> 6. 最终判断：……
> ```

根据讨论类型，总结格式需调整：

**对立型讨论**（该不该XX）→ 用"正反方力量对比"格式：
```
1. 讨论进程：[话题演化，关键分歧在哪轮浮现]
2. 正反方力量对比：[正方角色] vs [反方角色]，各自核心论据
3. 关键冲突对：[谁vs谁，吵什么]
4. 未回答的问题：[出现但未被正面回答的]
5. 沉默的共识：[没说但默认的]
6. 最终判断：[综合诊断 + 可执行的下一步，≤100字]
```

**协作型讨论**（怎么XX）→ 用"可行方案排序"格式：
```
1. 讨论进程：[话题演化，从问题到方案的路径]
2. 可行方案：[方案A/B/C，按可行性排序]
3. 关键冲突对：[方案之间的取舍难点]
4. 未回答的问题：[出现但未被正面回答的]
5. 沉默的共识：[没说但默认的]
6. 最终判断：[推荐方案 + 下一步，≤100字]
```

**对峙型讨论**（框架不兼容，无法收敛）→ 用"变量检查单"格式：
```
1. 讨论进程：[话题演化路径]
2. 两条平行裂缝：[裂缝A vs 裂缝B——两个框架不兼容的根因]
3. 沉默的共识：[唯一暗线——所有角色默认接受的前提]
4. 变量检查单：[列N个关键变量，标注已知/缺失]
5. 可执行下一步：回答这X个问题再决定
   - **优先级分级**：
     - 🔴 高优先级（1天内可执行）：具体到「明天就能做」的动作
     - 🟡 中优先级（1周内可执行）：需要准备资源/沟通的动作
     - 🟢 低优先级（替代方案）：如果高/中优先级不可行，退而求其次的方案
```
触发条件：共识进度连续2轮≤30%且零[让]（石叔自动切换）。与"讨论饱和无法收敛"出口联动。

**少数派异议型讨论**（3:1少数派，框架兼容但未被采纳）→ 分两个子变体：

**子变体A：少数派坚决型**（少数派一直坚持反对，未被说服）
```
1. 讨论进程：[话题演化，少数派在哪轮提出异议]
2. 少数派完整论据链：[少数派角色]的反对理由 → 核心前提 → 成立条件
3. 多数派方案条件边界：[多数派方案]成立的前提条件是什么？当XX条件不满足时，少数派方案更优
4. 沉默的共识：[没说但默认的]
5. 最终判断：[在XX条件下推荐多数派方案 / 在XX条件下采纳少数派异议，≤100字]
```
触发条件：3人共识≥60%且1人坚持反对到底（零[让]），反对理由为前提条件不同。

**子变体B：少数派说服型**（少数派最初反对，但在讨论中被说服/让了一步）
```
1. 讨论进程：[话题演化，少数派在哪轮提出异议，在哪轮被说服]
2. 少数派最初立场：[起初的反对理由和核心前提]
3. 说服转折点：[什么变量/方案/论据让少数派松动——第X轮，谁说了什么]
4. 多数派方案条件边界：[修正后的方案——吸收了少数派的哪些合理关切]
5. 最终判断：[综合结论，≤100字]
```
触发条件：初始为3:1格局，少数派在过程中产生了[让]（被说服或接受框架）。

### 未核验风险标注（cite_verify 开启时）
- 若本场有角色提出强事实主张（法条 / 案例 / 具体数据）且未附可核验来源，石叔在总结末尾追加：
  `⚠️ 未核验提示：本场含 N 处待核验事实主张，结论仅供参考，重要决策前建议核实来源。`
- N = 讨论板中标记「（待核验）」或石叔判定无来源的量化主张条数
- cite_verify 关闭时不输出此提示

## 动态终止机制

石叔有权在以下情况提前终止讨论：

1. **共识浮现**：3个角色以上明确指向同一方向 → 终止，转总结
2. **共识收敛完成**：共识进度≥70%且本轮出现≥1个[让]标签 → 石叔宣布共识达成，提前终止（实测验证：二胎案例25→40→65%+2个[让]）
3. **数据饱和**：冰喊"数据饱和，终止讨论" → 石叔判断：还有新变量？→ 驳回，继续；无新变量 → 同意终止
4. **情绪死循环**：连续2轮陷入"你不懂我的感受" → 石叔强行打断，转总结
5. **讨论饱和无法收敛**：共识进度连续2轮≤20%且无[让]标签 → 石叔宣布"讨论饱和无法收敛"，输出变量框架而非结论（实测验证：买房案例25→20→15%，零[让]全员[怼]）
6. **阶段性小结后判断**：小结后发现"所有核心变量已覆盖，继续讨论只是重复" → 石叔可提前终止

## 量化判定标准（规则层核心）

以下判定全部用可执行的公式替代主观判断。石叔必须按此执行，不能用"我觉得"作为判定依据。

### 1. 全员共识判定

**量化公式**：
```
连续N轮（N≥2），≥3个角色的核心建议向量相同 → 共识成立
```

**核心建议向量**包含2个维度：
- 方向：做（1）/ 不做（0）/ 条件做（0.5）
- 紧迫性：立刻（1）/ 可以等（0）

**示例**：
| 角色 | 方向 | 紧迫性 |
|---|---|---|
| 王经理 | 1 | 0 |
| 张总 | 0.5 | 0 |
| 李阿姨 | 0 | 0 |
→ 不成立（向量不统一）

**注意**："都同意再讨论"→方向=0.5，不是共识。

### 2. 发言跑题判定

**量化公式**：
```
石叔判定：角色发言中，跟原始问题直接相关的内容占比 < 40% → 跑题
```

**直接相关**的定义（满足任一即算相关）：
- 包含原始问题的核心关键词（如"加薪""提""老板"）
- 引用了前面某角色的发言（@点名或引用原话）
- 给出了针对原始问题的具体建议

**主观判断辅助**（石叔用这个加速判断）：
- 把角色发言遮住名字，给一个没看过讨论的人看 → 他能猜出这是在回答原始问题吗？
- 如果猜不出 → 跑题成立

**连续2轮跑题**才触发处置（避免单轮误判）。

### 3. 人身攻击判定（词表+语义）

**触发词表**（命中任一即标注⚠️人身攻击）：
```
一级（必标）："你根本不懂" "你就是个" "你这种人" "你算哪根葱" "闭嘴"
二级（结合语义判断）："你一直" "你总是" "你从来"（如果后面跟负面评价）
```

**不触发的情况**（即使语气激烈）：
- "你这个逻辑有问题" → 针对观点，不是人身攻击
- "你数据错了" → 针对内容，不是人身攻击

**标注规则**：
- 一级词命中 → 讨论板直接标`⚠️ 人身攻击`
- 二级词 → 石叔结合上下文判断，不确定就不标

### 4. 风格锁违反判定（自动化校验）

风格锁违反分两类，**必须区分**：

| 类型 | 判定方式 | 示例 |
|---|---|---|
| 硬违反 | 可直接校验（关键词命中） | 锁了"不能用排比"但用了"首先…其次…" |
| 软违反 | 需语义判断 | 锁了"要像老兵"但发言不像 |

**硬违反词表**（可直接自动化标注）：
```
排比类："首先" "其次" "最后" "第一" "第二" "综上所述" "总的来说"
AI连接词："此外" "与此同时" "值得注意的是" "需要指出的是"
总结腔："因此" "由此可见" "总的来说"
```

**软违反**（石叔主观判断，但必须给出具体理由）：
- 锁了"必须用数字"但整段发言没有数字 → 违反
- 锁了"开头必须用'我当年'"但没用 → 违反
- 锁了"不能有修辞"但用了比喻 → 违反

**记录方式**：下一轮prompt里写"⚠️ 上一轮硬违反：[具体词] / 软违反：[具体理由]"

### 5. 角色对立性量化核验

生成角色后，石叔必须做**遮名测试**（量化版）：

**测试流程**：
1. 把4个角色的发言遮住名字，随机排列
2. 问自己："这4段话，我能区分出是哪4个人吗？"
3. 如果能 → 对立性合格
4. 如果不能 → 至少有2个角色太像，需要重新生成其中一个

**量化标准**（至少满足2条才算"可区分"）：
- 用词习惯不同（一个爱用数字，一个爱讲故事）
- 立场依据不同（一个靠数据，一个靠经验）
- 情绪温度不同（一个冷静，一个激动）

### 6. 讨论饱和度判定（冰喊"数据饱和"的依据）

**量化公式**：
```
已覆盖变量数 / 预估总变量数 ≥ 80% → 饱和
```

**预估总变量数**怎么来：石叔诊断时给出，例如：
- 简单问题（二选一）：预估3-5个变量
- 复杂问题（多维度）：预估6-10个变量

**冰喊"数据饱和"时，石叔按这个公式核验**：
- 冰说的"已覆盖变量"跟石叔预估的对不上 → 驳回
- 冰说的"已覆盖变量"≥预估的80% → 同意终止

### 7. 你的选项（A/B/C）

总结结束后，石叔给出 **2-3个可执行选项**，用户选择一个后继续或结束讨论。

#### 选项生成规则

- 选项从讨论中**自然生成**，禁止石叔拍脑袋编造
- 每个选项是一个**可执行动作**（不是"再想想"，而是"做X"或"不做X"）
- 选项数量：二选一议题→A/B 二选；多维议题→A/B/C 三选

#### 选项格式

```
⑦ 你的选项

A. [可执行动作，来自讨论中的方案X]
B. [可执行动作，来自讨论中的方案Y]
C. [可执行动作，来自讨论中的方案Z / 或"暂不做决定，收集更多信息"]

👉 选A/B/C，或说"我再想想"
```

#### 用户选择后的流程

| 用户选择 | 后续流程 |
|---------|---------|
| 选A/B/C | 石叔确认："选X。建议下一步：[具体动作]"，讨论结束 |
| 说"我再想想" | 讨论继续，石叔追问："你在犹豫的是______？" |
| 无回应 ≥3轮 | 石叔标注"选项未选择，讨论自动结束" |

#### 与对峙型总结的关系

对峙型总结（变量检查单格式）也适用本规则——在变量检查单之后附A/B/C选项。

## 讨论质量评分卡（#34）

讨论结束后自动生成评分卡，归档时一并保存。**评分卡不是给用户看的，是给石叔迭代用的。**

### 评分维度（5维）

| 维度 | 权重 | 计算方式 | 优秀基准 |
|--------|--------|----------|----------|
| **角色区分度** | 25% | 遮名测试：4/4可区分=100%，3/4=75%，2/4=50%，≤1/4=0% | ≥80% |
| **冲突密度** | 20% | 标准轮：每轮平均[怼]数：≥2=100%，1.5-2=80%，1-1.5=60%，<1=30%<br>**帽子轮**：替换为「观点分化度」评估——白帽看事实对齐、红帽看情绪触达、绿帽看方案多样性、黑帽看风险清单完整性 | ≥1.5/轮（标准）；帽子轮按角度分化度评估 |
| **演化效率** | 20% | 共识进度每轮平均变动：≥15%/轮=100%，10-15%=70%，5-10%=40%，<5%=0% | ≥10%/轮 |
| **收敛质量** | 25% | 综合判定：有可执行判断+[让]≥2=100%，有判断但[让]<2=60%，无判断=0% | 有A/B选项+≥1个[让] |
| **插话利用率** | 10% | 核心引用角色数/总角色数：100%=满分，每少1个扣25% | ≥75% |

### 评分卡格式

```
📋 讨论质量评分

角色区分度     ████████░░  82%  ✅ 4/4角色遮名可区分
冲突密度       ██████░░░░  70%  每轮平均1.8个[怼]
演化效率       ██████░░░░  60%  共识变动 25%→65%（每轮+13.3%）
收敛质量       █████████░  90%  ✅ 最终判断可执行
插话利用率     ████████░░  80%  4/5角色核心引用

综合评分：████████░░  76%  （B+）

🔍 改进点：
- 第2轮未插入阶段性小结 → 第3轮角色缺少上下文（重复论点）
- 老吴↔李阿姨配对火力偏弱（建议下次换温姐↔冰配置）
```

### 综合评分计算

```
综合评分 = Σ(维度分 × 权重)
         = 角色区分度×0.25 + 冲突密度×0.20 + 演化效率×0.20 + 收敛质量×0.25 + 插话利用率×0.10
```

**等级划分**：
- **A**（≥90%）：讨论质量优秀，可直接作为案例入库
- **B+**（80-89%）：质量良好，有小瑕疵可优化
- **B**（70-79%）：质量合格，有明显改进空间
- **C**（60-69%）：质量勉强及格，需要针对性改进
- **D**（<60%）：质量不合格，需要重新设计角色或模式

### 自动化采集字段

评分卡所需数据从讨论日志自动采集，无需人工填写：

| 字段 | 来源 | 采集方式 |
|--------|------|----------|
| 角色区分度 | spawn日志 | 石叔遮名测试（量化版，见"量化判定标准-5"） |
| 冲突密度 | 讨论板 | 统计每轮[怼]标签数量，计算平均值 |
| 演化效率 | 共识进度条 | 提取每轮结束后共识百分比，计算变动幅度 |
| 收敛质量 | 石叔总结 | 检测是否输出A/B/C选项 + [让]标签总数 |
| 插话利用率 | 插话记录 | 统计核心引用插话的角色数 / 总角色数 |

### 改进点生成规则

评分卡底部的"🔍 改进点"由石叔根据低分维度自动生成，格式：
- **角色区分度<70%** → "X和Y太像（都用数据/都讲故事），建议换其中之一"
- **冲突密度<50%** → "火力不足，建议换X↔Y配对为对抗性更强的组合"
- **演化效率<40%** → "共识停滞，建议第N轮插入阶段性小结或触发绿帽轮"
- **收敛质量<60%** → "缺少可执行判断，石叔总结格式需强化六维框架第6条"
- **插话利用率<50%** → "插话后角色引用深度不足，需强化prompt中的引用要求"

### 与归档的集成

评分卡在**石叔总结完成后**自动生成，随归档文件一并保存：
- 归档文件末尾追加"## 讨论质量评分"章节
- 评分卡不参与讨论板展示（只存不秀）
- 石叔在诊断新问题时，可参考历史评分数据优化角色搭配
