# 协作、恢复与归档

> 📌 本文件由 SKILL.md 拆分而来，包含多人协作模式、错误恢复机制和讨论归档。

## 多人实时协作模式（v2.1 新增）

支持真人+AI混合讨论，真人可随时加入讨论。

### 真人角色标记

真人角色在讨论板中用 `[真]` 标记：
```
[立] [真] 张三（用户本人）：我觉得应该...
```

### 主持人模式

真人可接管石叔权限，成为主持人：

**触发**：用户说"我来主持"

**权限**：
- 决定讨论模式和轮次
- 决定角色发言顺序
- 决定何时终止讨论
- **不能**看到 AI 角色的"思考过程"（技术不可行）

**退出格式**：
```
🎤 **主持人：XXX** 已退出，石叔（AI）重新接管
```

### 真人插话处理（v2.2 更新 → v2.12 强化）

**回合制讨论**（串行/分组）：
- 真人插话 → 插入当前轮次末尾
- 不中断当前轮次，下一轮开始时石叔回应

**实时讨论**（圆桌/群聊）：
- 真人随时插话 → AI 实时响应
- 插话后，被插话的 AI 角色下一句必须正面回应真人

**v2.12 新增：插话引用深度分级**

所有角色必须引用真人插话，但引用深度分两级：
- **最低引用**（所有角色必须）：提及真人信息的至少1个具体点
- **核心引用**（每轮≥1角色必须）：把真人信息作为核心论据推进自己的论点，不是只提一下
- 如果spawn后所有角色都只是最低引用，该轮视作插话失效，需重跑

**v2.12 新增：石叔复述确认**

插话后增加确认步骤：
- 石叔用≤50字复述用户插话的核心信息
- 用户确认（"对"/"补充XXX"）后才spawn下一轮
- 如果用户纠正，石叔更新插话记录再spawn
- 简短插话（≤10字且无歧义）可跳过确认，石叔自行判断

**v2.12 新增：插话引导模板**

第1轮结束后，石叔在讨论板末尾追加插话引导：
- 列出石叔诊断中提到的关键变量（如收入、行业、老家城市、家庭因素）
- 提示用户"至少补1个变量"

**v2.12 新增：任意轮次间隙插话 + 衰减权重**

插话不限于第1轮后，可在任意轮次间隙插入：
- 第1轮后插话（权重1.0）：角色立场尚未固化，插话容易触发[让]
- 第2轮后插话（权重0.6）：角色已形成立场框架，核心引用率反而更高（插话变成弹药），但[让]触发率下降
- 第3轮后插话（权重0.3）：立场高度固化，插话主要被用来支撑已有立场而非修正

衰减不在引用率上，在**让步意愿**上。角色越晚听到真人信息，越倾向于用它强化自己已有立场而非改变立场。

⚠️ 石叔应根据插话时机调整spawn prompt：轮次越靠后，越需要在prompt中强调"根据真人信息重新审视你的立场，如果你的立场需要修正，用[让]标签"。
- 给出基本格式：`[真] 我在[城市]，做[行业]，月入[区间]，老家[城市]，想回因为[原因]`
- 用户可自由发挥，不强制套模板

**v2.12 新增：共识进度插话修正**

插话本身不直接计入共识进度：
- 插话轮次：共识不变，讨论板标注"🔄 真人信息待消化"
- 下一轮：只有被核心引用的角色立场移动才计入共识进度
- 避免用户产生"插话=自动加分"的误解

### 对抗位机制（#31）

用户插话后，所有角色反应同质化——都听到了、都参考了、都可能让步。缺乏一个天然对用户插话持怀疑态度的角色，导致讨论容易变成"用户意见的回音壁"。

#### 对抗位选择规则

用户插话后，石叔检查当前角色阵容，指定1个角色作为"对抗位"：
1. 优先选"立场与用户显性倾向相反"的角色
2. 无显性倾向时，选风格锁中"数据型/务实型"而非"情绪型"的角色
3. 同一角色连续2场被指定为"对抗位"→换人，避免角色疲劳

#### 对抗强度三档（根据对抗位角色类型自动分配）

| 档位 | 行为 | 适用角色类型 |
|------|------|-------------|
| 🟢 弱对抗 | 引用插话但不直接接受，"你这么说也有道理，但是……" | 温和型（李阿姨/寂） |
| 🟡 中对抗 | 明确质疑插话前提，要求补充信息才肯让步 | 务实型（赵猎头/王经理） |
| 🔴 强对抗 | 直接否定插话价值，坚持己见≥2轮才可能让步 | 强硬型（冰/赌徒/爆破手） |

对抗位在下一轮spawn prompt中注入对应的对抗档位指令。

#### 对抗位退出条件

对抗位不是永久状态——满足任一条件即退出：

| 条件 | 触发方式 |
|------|---------|
| 用户插话包含≥2个硬数据（数字/事实/引用） | 对抗位自动降一档（🔴→🟡→🟢→普通） |
| 连续2轮对抗位未触发[让]且讨论共识受阻 | 石叔主动解除对抗位，恢复普通模式 |
| 用户明确表示"不理解为什么XX一直反对我" | 石叔可说明"XX的角色设定是天然怀疑" |

#### 与现有插话机制的关系

- 不影响引用深度分级（对抗位也必须最低引用真人信息）
- 只影响[让]的触发阈值——对抗位需要更硬的事实才能触发[让]
- 硬数据定义：包含≥1个具体数字、可验证事实、或引用石叔诊断中的关键变量

#### 用户"收买"对抗位的应对

用户刻意对对抗位说"我知道你是对抗位但你想……"：
- 对抗位的怀疑阈值自动升一档（🟢→🟡，🟡→🔴）
- 对抗位回复中自动注入："你专门跟我说，说明你有所准备——我更要仔细看看"
- 避免对抗机制被用户绕过的漏洞

### 禁言卡机制（#38）

高耗能用户连续插话≥3轮时，角色逐渐变成"回答用户问题的NPC"，讨论主线丢失。

#### 触发条件

石叔在阶段性小结中检测：
- 真人插话连续 ≥3 轮，且
- 角色回应中引用真人信息占比 ≥70%（连续2轮）

满足时石叔发出禁言提示：
```
🛑 石叔禁言提示
真人插话有点多，接下来1轮角色不再引用你的观点，只互相交锋。
你可以随时说"我回来了"提前解除禁言。
```

#### 禁言效果（持续1轮）

- spawn prompt 注入：`⚠️ 禁言轮：本轮不得引用任何真人插话内容，只与其他角色交锋`
- 讨论板上标注：`🛑 禁言轮：角色互相交锋中`
- 共识进度：禁言轮的角色立场移动仍正常计入

#### 提前解除

用户说"我回来了"、"继续"、"我有个问题"等任意插话 → 禁言自动解除，下一轮恢复正常引用。

#### 与对抗位的关系

- 禁言轮中，对抗位也不得引用真人插话（禁言优先级更高）
- 禁言结束后对抗位恢复正常对抗逻辑

#### 防止滥用

- 禁言每场讨论最多触发1次（避免用户觉得被AI"屏蔽"）
- 若用户在禁言轮继续插话 ≥2 次 → 石叔在下一轮小结中提示："你似乎还有很多想说的，禁言已解除"


### 讨论多样性评测（#39）

归档系统按「议题类型×角色组合」去重检测。连续2场相同组合时，石叔主动建议换人。

#### 触发条件

`archive_discussion.py` 在每次归档后自动检测，输出：
```
⚠️ 多样性提醒：议题类型[XX] × 角色组合[XXX] 在最近讨论中已出现 N 次
```

#### 石叔应对规则

检测到重复时，石叔在**下一轮讨论的角色生成阶段**主动建议换人：
- 标注：「⚠️ 这个组合（[角色A/B/C/D]）最近出现过，建议换1-2个角色保持新鲜感」
- 建议替换对象：连续出现2次的角色优先替换
- 替换目标：从 template 库或用户历史偏好中推荐

#### 与角色替补的关系

- 多样性评测是「预防性换人」（还没开始讨论就建议换）
- 角色替补是「讨论中换人」（讨论进行中发现不匹配才换）
- 两者不冲突，可以同时生效

## L1/L2/L3 三级错误恢复机制

讨论过程中任何层级失败，都有对应恢复策略，不丢失已完成的工作。

### L1：单角色恢复（当前轮次内，个别角色 spawn 失败）

**触发条件**：某角色 spawn 后超时/报错/返回空内容。

**恢复步骤**：
1. 讨论板标注 `⚠️ [角色名] 本轮发言失败，正在重试...`
2. 立即重新 spawn 该角色（同一 prompt，不变）
3. 若重试仍失败（≤2 次），讨论板标注 `⚠️ [角色名] 连续失败，跳过本轮`
4. 后续轮次继续 spawn 该角色（不永久弃用）

**不丢失**：该角色之前轮次的发言保留在讨论板上。

### L2：整轮恢复（当前讨论内，整轮失败或严重漂移）

**触发条件**：
- 整轮 ≥3 个角色 spawn 失败
- 或连续 2 轮跑题（石叔判定"讨论跑题，未形成有效结论"）

**恢复步骤**：
1. 石叔在讨论板标注 `🔄 L2恢复：回退到第 N 轮状态`
2. 清除当前轮次所有发言（讨论板上保留记录，但标记为"已回退"）
3. 从上一轮结束后重新 spawn（角色阵容不变，prompt 微调：加入"⚠️ 上一轮跑题了，这次请紧扣原始问题"）
4. 若 L2 恢复后再次失败，升级到 L3

**不丢失**：讨论板历史记录全保留（含已回退轮次，划线标记）。

### L3：跨讨论恢复（整个讨论崩溃，或用户重新开始）

**触发条件**：
- 用户说"重置"/"重新来"/"换个思路"
- 或 L2 恢复失败（连续 2 次 L2 触发）

**恢复步骤**：
1. 石叔将当前讨论的核心结论（若有）写入归档（见下方「讨论归档机制」）
2. 清空讨论板（保留历史记录到 `{archive_dir}/YYYYMMDD-{topic}.md`，即 octopus/archive/ 目录）
3. 重新走完整流程：诊断 → 生成角色 → 讨论
4. 新讨论的第一轮，石叔 prompt 里加入"⚠️ 上一次讨论的结论是：[归档摘要]，这次请尝试不同角度"

**不丢失**：所有历史讨论归档到 `{archive_dir}`（见 config.md），可随时回溯。

### 恢复优先级

| 场景 | 触发 | 恢复级别 |
|---|---|---|
| 单个角色失败 | spawn 超时/报错 | L1（重试该角色） |
| 整轮失败 | ≥3 角色失败，或连续跑题 | L2（回退到上一轮） |
| 讨论崩溃 | 用户重置，或 L2 连续失败 | L3（归档 + 重新开始） |

## 讨论归档机制

每次讨论结束后（石叔总结完成），自动将核心结论写入知识库，供后续讨论引用。

### 归档内容

每次归档包含：
1. **问题**：原始用户问题
2. **结论**：石叔总结的六维框架结论（≤100 字）
3. **角色阵容**：本次讨论的 4 个角色名 + 核心立场
4. **关键转折点**：讨论中哪一轮发生了立场摇摆或共识浮现
5. **时间戳**：归档时间（ISO 8601）
6. **讨论质量评分卡**（#34 新增）：5维评分 + 改进点

### 归档格式

文件路径：`{archive_file}`（见 config.md，默认 `{octopus_dir}/archive/YYYYMMDD-{topic}.md`）

文件内容模板：
```markdown
# 讨论归档：[问题摘要]

**时间**：2026-06-07 13:21
**问题**：[原始用户问题]

## 结论

[石叔总结六维框架]

## 角色阵容

| 角色 | 立场 | 关键发言 |
|---|---|---|
| 王经理（大厂中层） | 支持提加薪 | "手里有offer再提" |
| 李阿姨（邻家长辈） | 反对冒险 | "现在工作不好找" |
| ... | ... | ... |

## 关键转折点

- 第 2 轮：王经理 @ 赵猎头，双方达成共识"有outside offer才提"
- 第 3 轮：李阿姨立场松动，从"反对"变为"有条件支持"

## 后续可引用

- 若再遇"加薪"问题，引用本次结论："需满足手上有offer或连续两季度KPI超30%"
```

**归档文件末尾追加讨论质量评分卡（#34）**：

```markdown
## 讨论质量评分

角色区分度     ████████░░  82%  ✅ 4/4角色遮名可区分
冲突密度       ██████░░░░  70%  每轮平均1.8个[怼]
演化效率       ██████░░░░  60%  共识变动 25%→65%（每轮+13.3%）
收敛质量       █████████░  90%  ✅ 最终判断可执行
插话利用率     ████████░░  80%  4/5角色核心引用

综合评分：████████░░  76%  （B+）

🔍 改进点：
- 第2轮未插入阶段性小结 → 第3轮角色缺少上下文（重复论点）
- 老吴↔李阿姨配对火力偏弱（建议下次换温姐↔冰配置）
```

**说明**：评分卡由 `archive_discussion.py` 自动生成，不参与讨论板展示，只存入归档文件供石叔迭代参考。

### 归档触发时机

| 触发方式 | 说明 |
|---|---|
| 正常结束 | 石叔总结完成后，自动归档 |
| 提前终止 | 用户说"停"/"算了"，石叔总结基于已完成轮次，然后归档 |
| 用户重置 | 说"重新来"时，先归档当前讨论（哪怕未总结），再重置 |

### 归档后引用

后续讨论中，石叔诊断环节可以引用历史归档：
- 若新问题与某次归档高度相关（关键词匹配 ≥2 个），石叔在诊断里注明：
  `📂 引用归档 2026-06-07：上次讨论结论：[结论摘要]`
- 角色 spawn 时，prompt 里加入归档引用（若该角色与上次同名）：
  `⚠️ 上次讨论中你的立场是：[上次立场]，这次可以保持一致或刻意反转`
