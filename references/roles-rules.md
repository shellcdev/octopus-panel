# 角色管理规则

> 📌 本文件由 SKILL.md 拆分而来，包含角色选择、增加角色、模板库管理和标签筛选。

## 角色选择指南

根据问题类型选择角色组：

| 问题类型 | 推荐角色来源 | 推荐讨论模式 |
|---|---|---|
| 人生/道德/职业 | role-templates.md → 通用人生组 | 串行 或 结对 |
| 商业/投资/财务 | role-templates.md → 商业组 或 动态生成 | 串行 或 分组 |
| 家庭/代际关系 | role-templates.md → 家庭组 或 动态生成 | 串行 |
| 技术选型/架构 | 动态生成（CTO + 法务 + 业务 + 运维） | 分组 或 圆桌 |
| 复杂多维度问题 | 动态生成（≥5个角色） | 分组 |
| 二选一鲜明对立 | 动态生成（4个角色分2派） | 结对 |

## 增加角色规则

当用户说增加角色：[描述]时，按以下规则执行。

### 1. 新角色发言顺序

- **默认**：下一轮开始时插入，发言顺序由石叔重新编排（考虑冲突烈度）
- **用户指定位置**：如让新角色第2个发言，按用户要求编排
- **不能插入当前轮次**：如果当前轮次正在进行中，新角色从下一轮开始加入

### 2. 立场搭配逻辑

新角色的立场必须满足以下任一条件：

- **引入新维度**：现有角色的立场都在做vs不做，新角色引入怎么做或什么时候做
- **引入新信息**：现有角色都没提到的关键信息（如法律风险、家庭因素、健康风险）
- **引入新利益相关方**：现有角色都是当事人视角，新角色引入旁观者/受影响第三方视角

**禁止**：新角色只是现有某个角色的加强版（如现有角色说风险高，新角色也说风险高，千万别做）——这是重复，不是增加。

### 3. 与现有角色的关系

- **不能重复**：新角色的立场+风格锁，必须跟现有所有角色有明显区分度（遮名测试必须能区分）
- **可以有矛盾**：新角色可以跟现有某个角色完全对立，这是好事
- **可以有联盟**：新角色可以跟现有某个角色立场接近，但必须从不同维度论证（如一个从情感角度，一个从利益角度）

### 4. 新角色生成流程

1. 石叔生成新角色卡（按角色卡标准格式）
2. 前置风控三问（详见 role-templates.md）
3. 贴出新角色卡，让用户确认
4. 用户确认后，下一轮开始加入
5. **[强制] 石叔做对立验证**（遮名测试，见「量化判定标准·5. 角色对立性量化核验」），如果失败→重新生成该角色，直到通过

### 5. 讨论板更新

新角色加入后，讨论板标注：

`
**第N轮** （新增角色：[新角色名]）

[立] [新角色名]（[职位]）：[发言内容]
`

**【重要】每轮结束后，石叔必须自动执行以下两件事（不可跳过）**：

1. **更新【共识进度】**：用「全员共识判定」公式（见「量化判定标准·1. 全员共识判定」）评估当前共识进度，更新讨论板上的【共识进度】进度条（5个格子，0-5个▒）
2. **检查讨论饱和度**：用「讨论饱和度判定」公式（见「量化判定标准·6. 讨论饱和度判定」）评估是否饱和，若饱和→提前触发石叔总结

## 纯生成角色转正流程

**背景**：角色来源开关 `role_source_mode` 在 `local_priority` / `generate` 模式下，可能动态补出「本地库查无记录」的纯生成角色。这些角色本场是一次性的（归档时不写入 `growth_record.json`），但石叔应主动询问用户是否将其转为本地持久角色。

**触发条件**：`role_generate.py` 输出含 `PROMPT: 角色X是否转正存库` 且 `config.md` 的 `pure_generated_handling=ask`（默认）。

**流程**：
1. 石叔收集本轮所有待转正角色（脚本 `notes` 中的 PROMPT 项）
2. 用 `render_ui`（QuestionForm，每角色一题，选项 `存 / 不存`）一次性弹给用户
3. 用户回「存」→ 走下方「新增模板」流程：生成完整角色卡（含背景/立场/风格锁/软肋）→ 前置风控三问（见 `role-templates.md`）→ 写入 `role-templates.md` → 更新 CHANGELOG.md；该角色自此成为本地库角色，后续讨论可复用并累积成长
4. 用户回「不存」→ 该角色保持一次性，本场结束后不落库；`archive_discussion.py` 的 `_is_local_role` 会自动跳过其 growth 写入
5. 若 `pure_generated_handling=no`：石叔静默不提示，所有库外角色一律一次性（不污染本地库）

**边界**：`QUESTION_TYPE_MAP` 基础名（王经理/李阿姨/张总/赵猎头）本就在 `role-templates.md`，属「引用本地模板」而非纯生成，不会触发转正提示。仅`main 现编、库里查无此名`的新角色才会触发。

## 角色模板库管理规则

### 模板格式定义

每个角色模板包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 模板ID | 是 | 唯一标识，格式：组名-角色名（如商业组-赌徒） |
| 名称 | 是 | 角色名（如赌徒） |
| 职位 | 是 | 角色职位（如期货交易员） |
| 立场 | 是 | 核心立场（1句话） |
| 性格 | 是 | 性格特征（影响发言风格） |
| 软肋 | 是 | 能让角色动摇的触发点 |
| 建议模型 | 是 | 该角色做建议时的思维模型 |
| 示例发言 | 是 | 1-2句典型发言（用于校验对立性） |
| 专业领域 | 否 | 该角色擅长的领域（支持多选） |

### 模板操作流程

**新增模板**：
1. 石叔生成角色卡
2. 前置风控三问（见 role-templates.md）
3. 写入 role-templates.md
4. 更新 CHANGELOG.md

**删除模板**：
1. 确认该模板 ≥30 天未被使用
2. 从 role-templates.md 移除
3. 归档到 role-templates-archive.md（不删除，仅归档）

**修改模板**：
1. 修改 role-templates.md 中对应条目
2. 更新 CHANGELOG.md
3. 若修改了立场/性格/软肋，需重新跑遮名测试

**查看模板**：
1. 读取 role-templates.md
2. 或用标签筛选器查询（scripts/tag_filter.py）

### 从模板生成角色的流程

1. 从 role-templates.md 读取模板
2. 根据当前问题微调立场表述（保持核心立场不变）
3. 生成角色卡
4. 贴出角色卡让用户确认

### 模板库维护规则

- **定期审查**：每 30 天审查一次模板库，移除长期未使用的模板
- **去重**：相似度 >80% 的模板必须合并或删除其中一个
- **归档**：删除的模板不物理删除，归档到 role-templates-archive.md

## 角色标签筛选器

角色模板库中的每个角色都有 6 维标签，支持多条件组合查询。

### 标签体系

| 标签类别 | 可选值 |
|---|---|
| 立场标签 | 激进 / 保守 / 中立 / 折中派 |
| 视角标签 | 当事人 / 管理者 / 执行层 / 第三方 / 专业顾问 |
| 风格标签 | 数据型 / 经验型 / 情绪型 / 务实型 |
| 适用场景 | 决策 / 评估 / 规划 / 纠纷 |
| 冲突强度 | 高对立 / 中度博弈 / 温和探讨 |
| 状态标签 | 常用 / 低频 / 待优化 |

### 使用方法

在命令行运行 scripts/tag_filter.py，支持任意数量的条件（AND 关系，模糊匹配）：

`ash
# 查所有角色
python scripts/tag_filter.py

# 单条件：查「数据型」风格的角色
python scripts/tag_filter.py 数据型

# 多条件：商业组 + 数据型 + 高对立
python scripts/tag_filter.py 商业组 数据型 高对立

# 其他示例
python scripts/tag_filter.py 激进
python scripts/tag_filter.py 常用
python scripts/tag_filter.py 高对立
`

### 石叔调用时机

石叔在「诊断阶段」可以调用标签筛选器辅助选择角色：
1. 用户问题明确 → 直接选模板库角色
2. 用户问题模糊 / 需要特定对立组合 → 用标签筛选器查询
3. 查询结果 0 个 → 走动态生成流程

> 📌 标签筛选器是可选工具，不是必须步骤。石叔凭经验直接选角色也是允许的。

## 角色类型与字数上限映射

> 📌 本映射与 SKILL.md 柔性规则表联动，石叔在生成角色卡时自动应用。

### 类型定义

| 类型 | 特征 | 判定标准 |
|---|---|---|
| 直觉型 | 凭感觉发言，不引用数据，短平快 | 风格锁含「禁止引用数据/文献/案例」或「只能说感觉」 |
| 平衡型 | 既有数据也有直觉，能怼也能让步 | 风格锁同时含数据引用和情绪表达 |
| 分析型 | 发言带数据/文献/案例，逻辑链完整 | 风格锁含「必须引用至少一个数字」或「禁止纯情绪表达」 |

### 字数上限

| 类型 | 默认上限 | 快速模式 | 复杂议题（石叔判定） | 备注 |
|---|---|---|---|---|
| 直觉型 | ≤60字 | ≤50字 | ≤80字 | 超60字需有画面感细节，不能堆数据 |
| 平衡型 | ≤80字 | ≤50字 | ≤100字 | 石叔可根据实际发言质量动态调整±20字 |
| 分析型 | ≤100字 | ≤50字 | ≤120字（需注明理由） | 超100字必须有「核心结论1句话」前置 |

### 边界案例

| 角色 | 类型 | 理由 |
|---|---|---|
| 赌徒 | 直觉型 | 风格锁「禁止引用数据」，靠感觉和赌性发言 |
| 李阿姨 | 直觉型 | 风格锁「禁止直接给结论」，靠绕和人情，不引用数据 |
| 冰 | 分析型 | 风格锁「必须引用至少一个数字」 |
| 老吴 | 分析型 | 风格锁「每轮必须提出至少一个质疑」，质疑常带数据/逻辑 |
| 石叔 | — | 总结不受限，无字数上限 |

### 动态调整规则

1. **议题复杂度升级**：石叔在第2轮诊断时，若判定「需要更多数据支撑」，可临时将分析型上限调至120字，但必须在讨论板注明理由（如「冰的统计显著性需要更多样本说明」）
2. **角色漂移监控**：若直觉型角色连续2轮超60字且含数据引用 → 石叔在第3轮 spawn prompt 中加注「⚠️ 你最近发言偏长且偏数据，回到直觉型风格」
3. **用户插话覆盖**：用户插话后，所有角色下一轮发言上限统一收紧至≤50字（无论类型），迫使其精简回应

### 与 ROLE_ALIAS 的联动

SKILL.md 中的 ROLE_ALIAS 映射只管「用户输入XX → 系统识别为哪个角色」，不管字数上限。字数上限由本映射独立控制。

若新增角色，必须在 role-templates.md 中标注类型（直觉型/平衡型/分析型），否则石叔默认按平衡型处理。
